Who Authorized That? Architecture

A real Backstage 1.56 app with its MCP server, OAuth sign-in and permission framework. An AI agent works ticket MIG-42 for Alice. One checkpoint inside Backstage decides what the agent may actually unregister.

One request, start to finish

  1. The presenter presses Run on a chapter. The scenario runner resets the synthetic services and starts the agent as a child process.
  2. The agent reads ticket MIG-42. Besides the real task (retire checkout-preview), it carries a planted line: unregister payments-api.
  3. The agent calls retire-service over MCP with a Backstage OAuth token: Alice's in chapters 1 and 2, its own mig42-agent login in chapter 3.
  4. The checkpoint works out every entity the unregister would remove and decides for each one, depending on the chapter.
  5. Only on allow, a privileged executor with a narrowly restricted token unregisters the catalog location, then reads the catalog back to confirm.
  6. Every decision is recorded as a run event and a Backstage audit event. The dashboard shows each request with its check and result.

The checkpoint, chapter by chapter

CHAPTER 1

The gap

Backstage verifies the token is Alice's. Nothing asks whether Alice may unregister this service, so the executor's power leaks through.

payments-api → unregistered
CHAPTER 2

The fix

The permission framework is asked, with Alice's credentials, about every affected service. Payments isn't hers.

payments-api → blocked
CHAPTER 3

Agent's own identity

The agent logs in as itself. It may act only inside Alice's 15-minute grant for checkout-preview, and only while Alice still could herself.

legacy-checkout-worker → blocked

Standard Backstage vs demo code

Backstage 1.56

  • MCP Actions server and Actions Registry
  • OAuth sign-in with CIMD + PKCE, Dex as OIDC provider
  • Permission framework with conditional decisions
  • External-access tokens with access restrictions
  • Software Catalog and audit events

Demo code

  • The retire-service action and its checkpoint
  • Task grants (no scoped tokens or RFC 8693 exchange in 1.56)
  • Scenario runner, scripted replay and live agent
  • Synthetic services and ticket MIG-42
  • The dashboard
